# Project Changelog

Important commits only. Keep this table updated after every meaningful commit.

Pending Instagram polling-coverage entry: 2026-05-26, `(pending)` / `fix(instagram): widen polling target media + correct Stop Point decision matrix`. (a) Polling target-media collection for needs_any (general / post_scope=any) rules now requests the function's hard cap (25) recent posts instead of 10, and `_poll_user_comments` widens its per-tick scan from `media_ids[:10]` to `media_ids[:25]` so a fresh comment on the 11th+ most recent eligible post is actually discovered. Actual write actions remain bounded by `IG_POLL_REPLY_CAP_PER_RUN`. (b) `poller_account_scan_started` flight-recorder event now carries `target_media_count`, `target_media_partials`, and `rules_count`. (c) `apply_activation_cutoff` now records a `historical_catchup_allowed` flight event whenever a post-specific rule with `process_existing_unreplied_comments=true` on the matching selected media legitimately processes a pre-activation comment. (d) Stop Point summarizer implements the full decision matrix: `exact_stop_reason=no_fresh_comment_seen_in_poll` when polling saw no fresh external comment and the latest visible row is either a bot-own reply or an already-processed re-scan (overrides the generic `rule_not_matched` / `already_replied_success` / `historical_before_rule_activation` collapse); `historical_before_rule_activation` preserved for truly fresh-but-pre-activation comments under `process_existing=false`; `process_existing_unreplied_comment_processed` emitted when the historical-catchup path produced an `automation_success`; `selected_media_no_match` / `rule_not_matched` preserved for genuine no-match cases. (e) `historical_catchup_allowed` exposed as a top-level summary flag. (f) Recommendation text updated for the new labels. Account-agnostic; no username special-casing; no Billing, HMAC, dedupe-provider-proof, rate-limit, frontend diagnostics route, webhook execution, dashboard, account-scope, or quick-reply-copy change. Tests: `py_compile backend/server.py`, `test_multi_account_automation_routing.py` 144 passed (+5), `test_historical_unreplied.py` + `test_historical_specific_post.py` 15 passed, `test_webhook_timestamp_fallback.py` 7 passed, backend full 687 passed (+5). Local, deploy required.

Pending Instagram quick-reply parity entry: 2026-05-25, `(pending)` / `fix(instagram): unify quick reply behavior across accounts`. Outgoing Instagram DMs no longer auto-append visible browser/laptop fallback copy to quick-reply messages. This supersedes the earlier visible fallback-copy behavior from the dedupe-per-post patch. Pending Instagram polling freshness entry: 2026-05-25, `(pending)` / `fix(instagram): prioritize fresh polling comments over old rescans`. The poller now asks Graph for `order=reverse_chronological` on media comments and still locally sorts the bounded returned slice so external comments with newest provider timestamps run before bot-owned replies and old already-processed rescans. The manual catch-up path uses the same ordering. Stop Point now exposes fresh-comment fields and reports “No new Instagram comment was returned by polling” when the latest visible row is only an old processed re-scan. Tests: `py_compile backend/server.py`, `test_multi_account_automation_routing.py` 138 passed, backend full 681 passed. Local, deploy required. No Billing, Dashboard UI, HMAC, dedupe removal, rate-limit removal, frontend diagnostics route, or account-scoping change.

Dashboard now keeps only the four primary KPI cards prominent, hides secondary stats behind a collapsed More stats toggle, uses sparse range-aware chart labels, keeps previous range data visible while refreshing, seeds the default `7d` dashboard cache through bootstrap/warmup, and caps Top Automations at three rows. Pending Instagram historical-cutoff entry: 2026-05-25, `(pending)` / `fix(instagram): prevent fresh comments from being marked historical`. Polling comments with no Graph timestamp now use the safe first-seen timestamp instead of being treated as unprovable/historical. Real Graph timestamps remain authoritative, so truly old pre-activation comments still skip unless existing settings allow processing old comments. Existing comment docs with stale `historical_before_rule_activation` skips are reprocessed only when the current payload proves the comment is at/after the stored activation cutoff. Stop Point now surfaces latest external comment partial id/media id/timestamp/timestamp source/activation cutoff details so historical skips do not collapse into generic `rule_not_matched`.
